# COV-008B: controlled admission experiments

Use the current producer and unchanged total work/player shares in isolated development JVMs. Keep production Java and the seven exporter artifacts unchanged. The experiment is a prerequisite to policy selection, not a learning-ready simulator or an assertion of game-wide benefit.

## Implementation boundary

Generate an isolated AiInputContext overlay from the exact checked-out source with two checked substitutions: initial allowance funding, and a gate immediately before the first capture debit after the existing admission/perspective checks. The prefix overlay forwards the full allowance and admits every capture. Run the same prefix fixture against unmodified production classes as an independent control. No original capture body, work charge, disclosure implementation, recorder, callback or writer is replaced. Compile into a separate directory; never overwrite target/classes or check out another revision.

The development gate uses only a per-original-chooser observation ordinal, public fixture turn, explicit experiment salt and remaining observation allowance. Hash admission uses a documented fixed 64-bit mixing function without engine RNG. Test four stride offsets to expose fixed callback-order aliasing; compare hash denominators four/eight and two salts each. These are deterministic admission rules, not independent unbiased probabilities for exhausted/adaptive records.

A reservation candidate initially funds half the original share and unlocks the other half once at public fixture turn 31. It neither refunds spent work nor adds to the total share. Before that turn, an empty first tranche is deliberately reserved; a traversal that empties it remains a charged failed attempt. Disclosure ingestion also uses the funded tranche. A short game ending before turn 31 strands the reserve. The controlled overlay may use reflection only to release the explicit held allowance in its own development State; the production state API is unchanged. This is not a proposed production lifecycle or concurrency contract.

Experimental skipped/reserved contexts use explicit EXPERIMENT_SAMPLED / EXPERIMENT_RESERVED reasons in development events. These events are not ordinary supported V28 traces, are not sent through the dataset exporter and must not become training examples. Every original recorder/callback still runs, including nested calls; the gate skips only its own input traversal. Source accounting must count all supported wrappers, not just admitted views. Report deliberate skips separately from admitted unavailable views and disclosure-driven budget costs.

## Workloads and measurement

Use two-player small state, four-player public disclosures, and a four-player state whose public board grows at turn 31. Long runs have 2,400 input invocations over 60 declared fixture turns; short runs have 240 over six turns. Each repeated cycle contains outer Damage assessment with nested Draw assessment, one numeric callback and one entity callback. The cycle supplies a deliberate four-slot aliasing test, not a production family-frequency estimate. Include inherited planning scopes and current received request/diagnostic work. Public disclosure ingestion begins before the first capture and refreshes during the run; attribute its actual debits separately. Inactive original players keep their own unchanged shares.

Record exact per-view work deltas and outside-capture disclosure deltas, available/failed/skipped counts, source and lifecycle reconciliation, family/nesting/turn windows, remaining/unreleased allowance and policy hashes. Charge partial failures; never substitute predicted work for actual producer debits or let sums of nested inclusive spans double count. Compare unchanged callback return/count/checksum and engine RNG tail across every policy. Bound prototype retained telemetry to aggregate windows and fixed family/status counters; do not keep all policy snapshots or live Cards/Games in results.

Measure whole-run current-thread CPU/allocation and entry-through-START-write spans, separating healthy, unavailable and deliberately omitted inputs. Entry spans exclude callbacks/terminals; whole-run spans include them and must not be added to their children. Use the actual streaming writer with a character-counting sink. Character totals are not UTF-8 bytes or physical I/O measurements. Exclude fixture creation and final JSON result encoding; disclose measurement/read overhead and JIT/order effects. Use discarded warmups, repeated rounds and reversed-order JVMs; do not turn cheap unavailable calls into a healthy-capture speedup.

## Acceptance and gap review

Validate exact funding/debit reconciliation, admission ordinals/rules, all four stride offsets, both salts/rates, early/late windows, short-run reserves, original results, nested links, source starts/terminals and no engine RNG use. Require production-prefix and overlay-prefix agreement on represented policies, availability, debits and callback/source counts. Reject missing/duplicate rounds or declarations, altered profile/fixture dimensions, bad status partitions, negative/unreconciled work, wrong gate decisions and false policy hashes. Unit tests should challenge those claims, not merely regenerate the probe output.

Controlled results cannot choose a production default alone. Actual games have different family frequencies, overlapping parent/search capture scopes, disclosure lifetimes, concurrency/cancellation and variable costs. Assign those real-game checks and producer/consumer omission-policy versioning to the remaining COV-008 work before COV-008C selection. OPT-005 retains broader host calibration, exact transient heap, full collector/UTF-8/I/O attribution and runtime optimization. Preserve COV-004 completeness limits and trainingReady=false throughout.
