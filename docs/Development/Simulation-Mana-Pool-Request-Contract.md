# COV-007A: floating-mana request and test-payment attribution

The [payment inventory](Simulation-Payment-Boundary-Inventory.md) establishes that ManaPool.payManaCostFromPool calls the same weighted tie-break during real and test payments. The current list-only controller callback loses this distinction and the paid ability/shard. An active outer callback cannot prove that a nested payment is real. Close this gap before adding source-ability selectors.

## Neutral engine request and original dispatch

Add an immutable engine-native ManaPoolChoiceContext containing the exact paid SpellAbility, ManaCostShard, boolean testPayment and byte colorsPaid received by the engine. It is callback-local request data, with no trace types, IDs, AI dependency or registry. Add a default PlayerController overload accepting the original list and this request; it delegates virtually to the original list-only method. Forward the actual test flag from ManaPool through a CostPayment.getMana overload. Preserve the existing five-argument helper as an unknown-request compatibility call. Empty and singleton best sets still return before controller dispatch; weighting, deduplication, list order, selected Mana identity, spending and refunds stay unchanged.

The AI's typed overload must also dispatch through the original virtual list-only callback, rather than substituting a private first-element policy. A private scoped single-use witness may associate the typed request only with its exact original chooser, installed base AI receiver and original list. Nested, unsupported, disabled-at-entry and unknown requests mask older witnesses; finally restores the prior scope. An overridden receiver cannot silently inherit the base implementation's proof. Never retain lists, Mana or abilities in exported data or a long-lived registry. Capture failure must not cause an extra callback or a fallback record with an older request.

Mark the existing shared AI test-payment implementation as PLANNING_WORKING_STATE before it performs probe work, preserving its result, mutations/refunds and exception. A typed test pool callback also establishes planning directly, including when called from an otherwise rules-state parent. Real non-test calls retain the actual inherited basis; non-test does not guarantee committed game work or successful payment. Keep the engine-supplied test flag independent of the context basis and result. Compatibility calls without a request retain their prior unknown input semantics.

## V19 permission and wire contract

At an admitted base AI typed tie-break, capture the own SELECTOR entry/current view at BEFORE_SELECTOR, before the original virtual callback returns its selected Mana. Retain PAYMENT_MANA_SELECTION/MANA_POOL_OPTIONS, parent/action linkage, existing diagnostic offered-mana prefix and selected source/player/color/snow fields. This is a pre-ranked distinct best-weight tie set, not the entire pool or all legal spending plans; no selectable mana/source option bindings are granted.

V19's independent receivedParameters component adds exactly MANA_POOL_REQUEST with testPayment:boolean, shard:the native ManaCostShard enum name, colorsPaid:signed byte. Forward values, never derive them from active ability state or rerun weighting. The converge sentinel -1 and other native byte values are received arguments, not legal masks. The existing schema-1 callbackParameters diagnostic envelope records these scalars; the policy projection must match them exactly. Cost restrictions, weights, X-by-color maps and detailed conversion matrices remain outside this partial permission. Unknown or null shard requests refuse parameters rather than inventing a value. Work is one component plus three fields under unchanged limits/shares.

Only this own V19 boundary can claim the new kind. Require its entry and BEFORE_SELECTOR timing; testPayment=true requires planning in both context and any captured entry. Nested selectors preserve their actors/basis; stage remains the existing inherited stage rather than a new claim of real payment. Keep V1/V2 inventories and earlier extensions frozen, adding conditional entry extension V9. Keep source accounting in the existing cell and old list-only events/absent inputs byte-identical. A test selection is an admitted hypothetical observation, not a new gameplay payment or proof that mana was spent. All examples remain trainingReady=false.
