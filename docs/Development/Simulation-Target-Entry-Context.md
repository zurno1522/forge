# COV-006: standalone target entries

This first COV-006 integration adds fresh V4 input to the existing standalone target-pool adapter. It also emits independently versioned `entryLocation` on existing audited standalone input boundaries, implementing the public clock contract from [COV-005](Simulation-Planning-Boundary-Audit.md#entry-location-contract-for-cov-006007). This is a per-family implementation increment; nested target/search records and modes remain subsequent COV-006 work.

## Producer and wire contract

At an audited standalone input boundary, source visibility and the existing rules/planning basis are established first. `entryLocation` captures the public turn, phase and turn-player ID before option traversal, view projection, publication or the original callback. It is independently frozen and contains no new allocator ID or engine-object reference. Capture occurs outside parent publication locks. The optional component's schema version is 1; the choice protocol remains version 1 and the input profile remains V4.

The component has exactly `schemaVersion`, `status`, `kind`, `timing`, `stateBasis`, `turn`, `phase`, `turnPlayerId` and `reason`. Captured selector/operation/application kinds require respectively `BEFORE_SELECTOR`, `BEFORE_OPERATION` and `AFTER_SELECTION_BEFORE_APPLICATION`, with an established rules/planning basis. Phase may be `UNESTABLISHED`; an unestablished turn player is null. Unavailable entries have null clocks, unestablished kind/timing/basis and an explicit `HIDDEN`, `INTERRUPTED`, `UNSUPPORTED` or `CAPTURE_FAILED` reason. Hidden and closed admission read no new clock getters. A clock failure remains visible through observation health and standalone failure counters; it does not replace the original callback or expose an exception message.

`AiTargetChoiceRecorder.choose/select` without an evaluation owner enters a fresh selector boundary. `selectedFrom/addSelected` observes a precomputed result at application entry: the old `poolSnapshotTiming:AT_TARGET_ADDITION` remains intact and the new input/entry timing is `AFTER_SELECTION_BEFORE_APPLICATION`. No selector is rerun. Non-targeting pool helpers retain their existing no-record path; this increment covers the existing targeting adapter, not every helper invocation. The existing recommendation, opponent-preference and actual target-addition provenance meanings remain unchanged.

Exact diagnostic pool objects are captured during the existing single bounded enumeration. V4 reuses those objects to establish supported current public diagnostic links. No second pool traversal, privileged object search or model-facing pool grant is introduced. Private, stale, LKI and unsupported option references stay unresolved under the existing binding contract. Recommendation callbacks still do not apply targets unless the original addition site does so.

Entry and view clocks use successive synchronous reads, not an atomic whole-engine snapshot. A slow or side-effecting option getter can change phase before projection; entry remains its earlier clock while the view and STARTED envelope retain their own current values. The validator checks the owning timing/state basis without equating these different clocks or repairing one from another. Completion cannot overwrite the entry snapshot.

## Decoder and reporting

`entry_location.py` validates exact fields, versions, public clocks, known player identity, unavailable reasons and kind/timing/state combinations. The standalone validator additionally checks the audited boundary and legacy target-pool timing. Target input requires the new independently located boundary; old target rows without it remain unchanged. Existing source masking and identity/incarnation checks apply to the diagnostic option prefix.

Coverage retains `knownInputBoundaryInventoryV1` unchanged. When entry components are present, an optional independently versioned `entryLocationAudit` reports their statuses, kinds, timings, state bases and reasons, with a separately named `knownInputBoundaryInventoryV2`. That inventory currently extends standalone targets; it does not retroactively certify legacy records or nested/search/mode coverage. Entry-audit records count present components only; absent entries provide no declaration, and overlapping observations are not unique gameplay decisions.

Captured entry clocks group under `ENTRY_LOCATION`; unavailable entry clocks stay null under `ENTRY_LOCATION_UNAVAILABLE`, even if an event or view has another clock. Absent capability retains the original choice-start/parent-container grouping. `playerId` remains the owning chooser; `turnPlayerId` is the active turn player, not a replacement actor. Entry diagnostics and raw IDs remain outside policy features and do not change `trainingReady=false`.

Source accounting retains COV-001A's original-controller standalone scope. The same callback is counted once; an unavailable view remains a retained base record, distinct from an omitted invocation. Entry capture adds no parent/nested invocation denominator. The 256,000-unit game traversal allowance and player shares remain unchanged; added target views can exhaust that share earlier. COV-008 owns availability-policy changes.

## Review and remaining COV-006 work

The initial source/consumer review covers callback-once behavior, original result/exception identity, one-pass pools, planning cleanup, precomputed application timing, public/private option associations, masked-source clocks and legacy absence. No complete target-alternative domain, effect-specific amount, printed ability semantics or training-ready example is claimed. Those inputs require independently audited family contracts; diagnostic pool membership is not a feature permission.

Next COV-006 increments must add nested target and final search-operation entry/context capture outside parent publication locks, pass precomputed timing before capture, preserve timeout/admission ownership, and define their source/receipt accounting explicitly. Controller modes must distinguish cached/planned operations from the actual Charm selector and enter the audited planning scope. Repeated effect picks require current remaining domains and outer constraints where supported. Each increment has its own commit and gap review before moving to COV-007. The two unsupported invocations found in the OPT-005 game remain unclassified until source evidence identifies them; static nullable mana-pool contexts are an audit candidate, not proof of their origin.

### Capture-closure hardening

The nested-integration review found that a newly added entry-clock getter could throw after admission closed and still mark observation health as failed. Standalone options/input capture had the same late-failure edge. Closed capture now discards those failures, stops new projection work and permanently retires the unstarted observation. Its original callback still runs once; reenabling recording during that callback cannot revive the abandoned token and emit an orphan terminal.

Three blocked-getter regressions cover clock, options and input projection failures after admission closes, including recording being reenabled by the original callback. All 56 focused Java tests pass. No schema or budget change; the subsequent nested integration will supply the next full-suite check. See [closure-hardening evidence](assessments/COV-006-standalone/closure-hardening.json).

### Hidden-entry consistency

The subsequent decoder review found an accepted contradiction: a context explicitly unavailable because its source was hidden could still carry a captured public entry kind/clock. The new regression failed before the fix. Such a context now requires the matching hidden, unavailable entry; existing source-boundary masking checks still apply. All 163 Python tests pass after the fix. This changes validation of contradictory new metadata, not valid legacy messages or production field meanings.

The mode-family review also reproduced a producer inconsistency: masked standalone inputs still carried their original selector/operation timing and planning basis. Those two fields now use `UNESTABLISHED`, matching the hidden entry and search protocol. The internal planning scope remains intact for descendants; diagnostic envelope fields are not promoted into policy. Two new regression cases failed with the exposed timings before the change. The final focused run passes 56 Java tests; all 181 Python tests pass. This narrow correction changes neither profile V4 nor the budget and preserves callback identity/count, hidden supplier bypass and legacy decoder compatibility. Mode integration follows separately.

### Result-projection closure hardening

The repeated-choice integration review reproduced a remaining shared-adapter fault: a result projection blocked outside the parent monitor could throw after the parent timed out or recording closed, and still poison game observation health. Such obsolete projection failures are now discarded using the observation's existing admission owner. The original callback result is preserved; no late terminal or revived parent is emitted. A live projection failure remains visible. Publication failures retain their existing handling.

Two blocked-projection regressions failed before the fix; a third checks that live failure visibility remains intact. All 59 focused Java tests pass during the ongoing outer-entity integration. The later increment supplies the next combined full-suite check; no isolated full-suite result is claimed for this small correction.
