# OPT-005: phase-profiler exception unwinding

The failure-path audit reproduced a development-profiler defect: a callee can throw without an ATHROW instruction in its caller. Normal-return/explicit-throw hooks left capture, freeze and publication spans open after such propagation. A comparator exception also skipped the old instruction-after-sort cleanup. Subsequent samples could be misattributed and final reconciliation failed with Unbalanced instrumentation. This is a measurement-tool defect, not a Forge rules/card bug.

The agent now installs catch-all cleanup for its tracked methods and rethrows the original Throwable. A small typed sort bridge uses try/finally instead of an unmatched before/after instruction pair. Failed freezes clear their sampled source roots. A sampling diagnostic that occurs after normal span retirement remains visible without retiring the span twice or retaining that source. The injected handler needs only the thrown value, preserving existing method frames and avoiding engine-class loading to compute a new hierarchy.

Executable tests use the actual agent/metrics against isolated bytecode fixtures. Nine timing failure cases cover direct and propagated capture/freeze/publication exceptions, an Error, nested freezes and comparator failures, with unchanged throwable identity and healthy recovery. Additional memory scopes check failed-source cleanup and visible sampler diagnostics both inside and outside capture. The same final fixtures fail against source-pinned agent 159b6c05bce with Unbalanced instrumentation and pass after the fix. Fixture classes are kept off the real Forge classpath and out of the agent JAR.

The native boundary check loads actual Game, AiInputContext and AiDecisionEvent classes. A failed input supplier preserves its exception, the next healthy capture keeps ordinal 2, invalid JSON freezing remains rejected, and a native subscriber failure remains visible. All phase counts reconcile. A separate small control/profile workload pair validates actual class verification and healthy/refused/exhaustion paths across the five fixtures. It is a smoke check, not another timing comparison or a played game. All 368 Python tests pass; no production Java changed.

The earlier controlled-cost cohort contained healthy/refused samples with balanced spans and rejected failed fixtures. Its source-pinned results keep their recorded instrumentation build. Do not pool future profiled timings with that build without naming the instrumentation difference. Uninstrumented production behavior, defaults and budgets are unchanged.

This closes the profiler prerequisite for the next OPT-005 failure, later-family and collector/UTF-8 cohorts. Physical-path attribution, native Monte Carlo/resource validation and the optional hash gate remain open under the [checkpoint contract](Simulation-V29-Cost-Checkpoint-Contract.md). Sampling payload unions still do not establish exact transient live heap. All reports remain trainingReady=false.
