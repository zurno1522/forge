# COV-006: mode entry and current input

Mode capture has two separate boundaries. `CHARM_MODE_HEURISTIC` surrounds the actual Charm heuristic and uses `SELECTOR` / `BEFORE_SELECTOR`. `CONTROLLER_MODES` surrounds the controller operation and uses `OPERATION` / `BEFORE_OPERATION`: that operation can return a cached choice, accept an intercepted search plan, apply planned targets or invoke trigger preparation. Recording never reruns a selector to classify a return.

Both boundaries enter an explicit `PLANNING_WORKING_STATE` scope before observation. Candidate faces, resources, targets and prepared mode combinations can be hypothetical. A callback occurring during stack resolution does not prove committed input; descendants inherit the planning scope, which is restored on normal return and exceptions. Each observation captures its own entry clock and fresh permitted view before the original callback. The entry and projection are successive reads, not an atomic engine snapshot.

This first increment retains profile V4. Actual offered mode identities, indices, definition indices, bounds and repetition flags stay in diagnostic `options`; returned/stored plans stay in terminal `selection`. Mode identities and offered-domain membership do not become permitted model inputs. Typed mode bounds require their own versioned permission and decoder contract before this family is complete. A captured view alone does not establish full legal alternatives, cached-plan cause, effect semantics, rewards or training readiness.

Source visibility precedes clock, option and input reads. A masked source supplies an unavailable view and entry with `HIDDEN`, without exposing selector/operation timing or planning basis through the new input component. Disabled and simulation-copy games bypass all observation work. Existing fixed traversal budgets and standalone source accounting apply; input exhaustion does not suppress the original callback or its result.

## Export compatibility

The V1 and V2 boundary inventories remain frozen. A separate, conditional `knownInputBoundaryInventoryExtensionV3` mode inventory extension is emitted only for mode boundaries with present entry components. The extension lists only observed mode boundaries with entries; reports without such components retain their existing values. Existing V1 audit classification counters still describe V1, even for boundaries supported by the extension. Present mode inputs require their own entry and the audited family timing/planning basis. Options remain diagnostic and no option-to-entity bindings or typed prompt are authorized by this increment. All exported examples retain `trainingReady=false`.

An outer operation is not an extra selector invocation. Legacy records acquire no fresh clock by inference.

Typed received mode bounds and remaining repeated-pick arguments remain COV-006 and precede COV-007. Earlier X calculation and actual inner payment/mana seams remain COV-007.
