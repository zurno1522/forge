# COV-006: zone choices with movement between callbacks

Heist and Draft need their own audited operation branches. They cannot inherit the ordinary loop's append-before-receipt position. Reuse the generic game/controller callback and bounded observer, keeping movement, random draws, generated objects, effects and trigger delivery in their original order.

| Branch | Request | Receipt boundary | Terminal collection |
| --- | --- | --- | --- |
| `HEIST` | Received `Num`, Exile from Library; source player is the targeted library owner, decider is the heisting player | Immediately after the original callback and before `canExiledBy` or movement | The original successfully heisted, moved cards |
| `DRAFT` | Received `DraftNum`, None from an empty origin list; source/decider is the drafting player | Immediately after the original callback and before the original move to None | The original drafted collection before its later moves to Hand |

Keep null/error behavior original. Heist's rejection of a non-null card still counts as a non-null callback return, with no retained card or movement. Empty random offers still skip the selector. Draft's shuffled spellbook, substitutions, balanced-card lookup and card creation remain inside the original loop. Do not turn generated options into public policy inputs.

A receipt names the object/incarnation at return, before movement. At the next entry its old incarnation or private/unrepresented identity can resolve to null. Never substitute the moved object or claim an earlier return's name as newly public. Attempt ordinal, loop position, non-null returns, retained count and actual movement remain separate facts. No new persistent registry is needed.

## Exact dispatch proof

Both loops construct origin lists at the individual call. Draft specifically supplies a fresh mutable empty list on every call. Preserve those objects rather than hoisting them into the operation request. Extend the passive observer with a before-selector overload taking the actual per-dispatch origins object. Its default delegates to the existing hook. The base AI observer retains that exact object only until return/retirement and a visible child can claim it once.

For these two branches only, allow an actual origin-list object distinct from the outer descriptor when its bounded ordered enum values equal the received operation request. Keep the old identity requirement for ordinary/named/per-type requests. Perform any comparison only in a visible admitted selector supplier, outside publication locks; recheck ownership after reads and discard late results/faults. Do not inspect origin lists in off, copied, hidden or unsupported callbacks. Mismatched objects, destinations, roles or values cannot acquire progress permission.

## Implementation validation and gap review

V12 implements both branches. The targeted reactor run passes 141 Java tests, including actual two-pick Heist/Draft resolution, pre-movement receipts, fresh per-dispatch origin objects, Draft's original mutable empty lists, exact origin-object refusal, bounded value comparison, original callback exceptions, zero/empty cases, seeded recording-on/off movement and RNG parity, three bypass paths, live failure ownership and four blocked-comparison closure/late-result cases. Rejected Heist returns are exercised with a real `CantExile` static rule: two non-null returns retain zero cards and leave the library intact. Python passes 223 tests, including branch/profile refusal, canonical zone/role constraints, unavailable prompts and ownership mismatches. The previous V11 full reactor passed; this increment does not claim another full-suite run.

All seven export artifacts remain byte-identical across 168 V1–V11 saved streams. Two fresh games finish normally, reconcile source/collector accounting without observation failures, retain two opening shuffles before `GAME_STARTED` and preserve full/filtered dataset, choices, examples and validation bytes; coverage agrees except source-record totals. The ordinary fixture's normalized engine events equal V11. The new complete-game fixture samples Heist, but not Draft. Separate actual engine-resolution excerpts cover Heist, Draft and rejected Heist, and all eighteen lifecycle events (nine operations/selectors) pass decoder validation. The excerpts are explicitly not complete-game traces.

No demonstrated defect remains in the new moving-loop integration. Review did find a prior COV-006 origin-diagnostic hardening gap: V8/V9 policy projection bounds origin lists, but the option serializers still use an unbounded stream and can emit a list the decoder refuses. This must be corrected in a separate hardening commit before the next design item. Ordinary/named/EACH behavior and valid legacy wire output must stay unchanged; source accounting must distinguish unsupported metadata from observation faults and retain the original callback. This is an instrumentation defect, not an engine/card rule defect.

The remaining spell-ability family has six engine caller classes, including Venture, CopySpellAbility, AssignGroup and ActivateAbility as well as ChooseGeneric/VillainousChoice. Its opaque maps, generated/stack abilities and repeated-return semantics need their own contract. COV-004 retains completeness/knowledge requirements; COV-007 payment/X; COV-008 availability; OPT-005 expanded movement-loop observer/comparison/context costs and broader Draft/EACH game sampling. All examples remain `trainingReady=false`; no budget or policy optimization is bundled here.
