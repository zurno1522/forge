# COV-006: disabled nested entity-operation masking

Review after V15 reproduces an observation-ownership defect in the earlier entity wrapper. An admitted outer operation can have a pending selector dispatch. A nested operation entered with recording disabled previously called its callback directly. If that callback reenabled recording, its single selector could claim the older operation's pending history, because the nested wrapper had skipped the history scope that should mask it. Matching IDs or adjacent records cannot make that nested selector the original announced dispatch.

The disabled path now runs through `AiEntitySelectionHistory.operation` with a null admission owner. That existing scope removes the older frame for the callback and restores it in `finally`. It inspects no offers, returns, map arguments or new engine getters, and preserves callback results/errors. The proper outer selector can still claim its original dispatch after the nested operation returns. Zone and spell operation wrappers already use this masking pattern; the source review finds no other history-operation wrapper with the same fast-path omission.

The new regression fails on `151c82d17ca`: the nested selector incorrectly receives a complete empty selectionSequence. After the fix, it has the ordinary single-entity prompt with history unknown, while the proper outer selectors retain counts zero then one and the correct earlier public card association. The returned objects/order and observation health are unchanged. The patched focused reactor passes 116 cases across entity, zone and spell request/history families. No new source slot, profile/version, feature permission or decoder behavior is introduced; the three exporter modules are byte-identical to V15. No new Python/full-suite run is claimed.

A fresh repeated-entity game and the same-seed pre-fix recorder-class overlay both finish normally, with equal normalized non-AI engine events. Full/filtered datasets, choices, examples and validation match within each run; coverage agrees except source-record totals, source/collector accounting reconciles with no observation failures, and both retain two opening shuffles before GAME_STARTED. The normal game samples one entity operation, two entity selectors and one history-bearing selector. Disabled/re-enabled nesting is exercised by the regression, not claimed as naturally sampled in those games. The isolated overlay does not change the checkout and supplies no whole-build performance claim.

This is a defect in branch-specific observation ownership under PR-003, not an established Forge rules/card bug. Review closes this prior COV-006 gap. The direct numeric/entity parameter and mode-input audit follows; broader domain/ability knowledge remains COV-004, payment/X COV-007, availability COV-008 and scoped-mask costs OPT-005. All examples remain unready. The separately reproduced pre-V15 Monte Carlo scavenge scenario instability remains validation triage.
