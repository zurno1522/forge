# COV-006: remaining received parameters and mode-input boundaries

V15 and the entity off-path fix close controller-local spell history and the reproduced earlier ownership gap. The remaining COV-006 work is the received argument maps of already audited numeric/entity selectors. This source/design inventory does not add runtime fields, infer unobserved calls or certify complete examples. Source hashes describe `358d66c63d8`; the older boundary inventories retain their historical meaning.

## Source findings

The inventory records qualified literal engine call occurrences, including overloads and helpers; they are not runtime invocation counts. Handler reads include protected card/player/attackable dispatch and the delegated `PlayAi.chooseSingleCardInPlanning` helper. Auditing only methods named chooseSingleEntity or public methods misses these inputs.

The human single-entity implementation does not interpret the parameter map: it uses the rendered message and its own temporary display. A map's existence does not prove delivery or permission to every value. This design grants only audited typed invocation fields and current public entity-role associations; it does not serialize titles, grant hidden card identities or infer full effect semantics from map keys. Unknown shapes remain unavailable.

`CounterType` is an open interface. Its native enum and native final custom/keyword records are auditable; arbitrary implementations cannot be trusted to supply a safe name. Parameter classification must not enumerate an arbitrary map, evaluate unknown objects or call arbitrary toString methods.

## Execution order and contract choice

1. Add one independent V16 **receivedParameters** context component for bounded scalar/current-role request shapes at the two existing boundaries. Keep request parameters independent of prompt/history. A missing parameter component must not silently become NONE, and unsupported parameters need not erase an independently valid range or already declared history prompt. This avoids adding another family field and variants to the growing AiPromptInput union.
2. Add bounded attachment/attacker role collections in a separate implementation/permission increment, with whole-list completeness and safe associations. Do not promote a prefix to a complete request, or attach offered-pool permission to a list merely because it contains public cards.
3. Re-review the finite audited numeric/entity argument scope, then proceed to COV-007 payment/source and earlier X work. Keep each implementation and gap review in its own commit.

The first increment uses an AI-private final carrier containing one detached diagnostic receipt plus temporary exact role objects for same-entry projection. It is supplied explicitly to the current capture; no ambient lookup, game API, parent borrowing, registry or durable raw-object reference is introduced. Reuse current player/card bindings and incarnation checks. Preserve the original map, title, collection, callback, delayed-reveal timing, result and exception. Do not recompute policy or move engine getters into publication locks.

V16 globally adds `coverage.receivedParameters` and nullable `policy.receivedParameters`. Default capability at other boundaries is UNSUPPORTED; an unavailable whole context declares UNAVAILABLE. A successful component declares `RECEIVED_CALLBACK_PARAMETERS_V1`. Audited callbacks add diagnostic `options.callbackParameters` with schema 1, coverage COMPLETE/UNSUPPORTED/UNAVAILABLE, a declared shape kind, detached typed values and a reason. This receipt is excluded from features. The decoder requires the own entry/profile/boundary, exact fields/types and same-view role consistency. No source slots or entry inventories change.

Recognize only null/canonical-empty maps and exact native HashMaps with a bounded, exact whitelisted key set; inspect at most three known values. Unknown map implementations/subclasses, extra keys, unsupported/null values or unrecognized shapes are unsupported without enumeration or unknown-value getters. NONE means a proved no-parameter request, never a fallback for an unknown map. Supported scalar shapes are VOTER, COUNTER_AMOUNT, COUNTER_TRANSFER_AMOUNT, ENTITY_CARD_ROLE (Attach/Attacker/Partner), ENTITY_TARGET_ROLE, ENTITY_MANA_VALUE_LIMIT and ENTITY_COUNTER_REQUEST (CounterType, optional Amount and Target). Preserve signed ints. Capture only native CounterType names, whole and at most 256 characters; overlong values make the component unavailable, without truncation or arbitrary representation.

Project current Player roles by exact current-game identity. Project Card roles only through an exact represented public object and the receipt's same incarnation; reject LKI, stale, foreign/equal-ID or otherwise unproved roles. Private/unrepresented role identities make this component unavailable with UNRESOLVED_BINDING. Do not substitute raw IDs, names, guessed source/controller roles or references from another view. The original callback still receives the original value. Supplied CounterType/Amount/CMCLimit are request data, not a complete cost or legal-domain description.

A trusted final carrier permits received parameter fields in planning while retaining PLANNING_WORKING_STATE. It grants no additional planning permission to the existing numeric range prompt or unrelated suppliers. Charge the existing fixed work allowance for the component and each projected field; retain the 256,000/game limit and equal original-player shares. Hidden/off/copy paths do not inspect the new receipt supplier. Live getter faults remain visible observation failures, while late values/faults after closure are discarded. Metadata work remains bounded, and closure must not wait for a blocked getter.

Require meaningful actual controller/handler cases (including voter min/max and counter-role requests), frozen pre-callback values, exact forwarding, private/stale/foreign rejection, unsupported map/value noninspection, bounds, fixed work, bypass and closure. Validate diagnostic/projection equality, no feature/role injection, old wire refusal, whole-context absence, full/filtered parity, actual output, legacy bytes and opening shuffle order. Reports count the new component declarations without claiming complete learning examples. Every example remains trainingReady=false.

## Mode semantics and other gap owners

Charm's existing selector/operation entries receive min/max/repeat bounds. Pawprint limits are calculated inside chooseOptionsAi after the selector entry; dependent modes mutate the working chain; Escalate/Spree/Tiered affordability probes temporarily chain chosen modes and call ComputerUtilCost. Recomputing these for an earlier snapshot or calling a cached return a fresh selection would be incorrect. Those are intrinsic ability/action-domain semantics under COV-004 and actual cost/resource probes under COV-007, not missing primitive callback arguments. COV-006's current received-argument work does not claim them complete. COV-004 also retains static spell definitions/associations, full option/domain permission and longer engine-owned histories outside the audited operations.

New uninstrumented families or additional external loops retain unknown counts/history and separate future entry designs; equal IDs or nearby events are insufficient to create owners. COV-008 owns availability policy, and OPT-005 owns new carrier/classification/projection/export costs, calibration and the independently reproduced scavenge scenario instability's performance investigation. No optimization, budget increase or learning policy is bundled with this source/design item.

## V16 scalar/current-role implementation and review

The first increment is implemented. `coverage.receivedParameters` is RECEIVED_CALLBACK_PARAMETERS_V1, UNSUPPORTED (no audited component at this boundary) or UNAVAILABLE. `policy.receivedParameters` is null unless captured. It is independent of prompt/history and is gated to the own numeric-range or single-entity entry. Parent, nested-target, search, payment, mode and spell contexts cannot borrow that permission. Planning parameters retain their working-state basis without granting a planning numeric domain.

The diagnostic `callbackParameters` has exactly schemaVersion (1), coverage, kind, values and reason. COMPLETE has a known shape, exact typed values and null reason. UNSUPPORTED has null kind/values and reason UNSUPPORTED. A bounded native counter-name refusal has a known kind, null values and reason OUTSIDE_CAPTURED_PREFIX. Failed/private role projection does not rewrite the captured receipt: the independent component becomes unavailable with UNRESOLVED_BINDING. Raw role references remain diagnostic.

| Kind | Values/projected fields |
| --- | --- |
| NONE | Empty values; projected kind only. |
| VOTER | voter Player role. |
| COUNTER_AMOUNT | target Card/Player role and counterType name. |
| COUNTER_TRANSFER_AMOUNT | source/target Card/Player roles and counterType name. |
| ENTITY_CARD_ROLE | role Attach/Attacker/Partner and entity Card role. |
| ENTITY_TARGET_ROLE | target Card/Player role. |
| ENTITY_MANA_VALUE_LIMIT | Exact signed int manaValueLimit. |
| ENTITY_COUNTER_REQUEST | counterType, nullable amount and nullable target. Null means that optional argument was absent in the proved shape; an explicitly null supplied value is unsupported. |

Role values in diagnostics are detached typed references; the projection contains only this view's safely proved local reference. No new engine API, accounting slot, inventory extension, identity allocator or AiPromptInput family variant is added. Classification visits at most three known map values; projection charges one component unit plus one per declared field. Existing limits/shares remain unchanged.
