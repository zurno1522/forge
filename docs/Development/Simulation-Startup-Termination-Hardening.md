# Startup termination race found during COV-008B

A native one-second Commander cancellation produced two GAME_OUTCOME records. The first forced draw arrived after GAME_STARTED; initialization then continued through drawing/mulligans, emitted a second outcome and began the first turn. No admission State was registered in this run, so the reserve policy had not executed. The ordinary reader correctly rejects the duplicate outcome; that failing trace is retained as rejected evidence.

GameAction.startGame checked terminal state before opening actions and after mulligans, but its later writes of Mulligan and Play could overwrite GameOver. SimulateMatch's cancellation callback and final cleanup were already synchronized and joined the worker; the worker could still revive the game before cleanup. Both startup transitions now check isGameOver and set the next stage under the same Game monitor as setGameOver. No UI callback, opening action, script or policy is run under the added critical sections. Existing normal event order is retained, including initial shuffles before GAME_STARTED. Game.setAge and explicit snapshot/restore/restart APIs are unchanged.

Two native regressions finish the game during GAME_STARTED and during an actual registered start-of-game GainLife script, respectively. They use Puzzle rules to isolate the startup transitions from mulligan heuristics. Both fail before the fix because startup replaces the completed GameOutcome. After the fix, the original outcome remains, only one outcome is emitted and no first turn begins. The focused seven-class Maven run passes 37 cases, including simulation cancellation/trace closure, collector failure handling and restart behavior. This is a focused result, not a full-reactor claim.

The fetched upstream master has the same unconditional startup setters and unconditional Game.setAge. All 242 currently open PR titles/bodies were reviewed for related startup/cancellation/simulation work; changed filenames were inspected for seven nearest candidates. No superseding fix was identified in that review. This is not an exhaustive patch audit of unrelated PRs or an upstream runtime reproduction. PR-006 records the candidate; adapt the branch-specific draw helper in the regression and rerun upstream CI before proposing a PR. No upstream PR was opened.

Current/prior-gap review finds the reproduced revival defect closed. COV-008B resumes actual-game validation with this fix in a separate commit. Preserve the original invalid trace and original timeout classification; never relax the duplicate-outcome validator. Early timeouts can legitimately precede GAME_STARTED and carry sparse, explicitly complete zero-invocation ledgers; their absent meter registry establishes no input-capture coverage. Longer diagnostic replays remain separate from censored originals. Global lifecycle/cancellation behavior beyond these two startup transitions is not claimed by this patch.
