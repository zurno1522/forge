# COV-006: controller-owned repeated entity operation

`chooseEntitiesForEffect` now records an outer `EFFECT_MULTI_ENTITY_SELECTION` at `CONTROLLER_EFFECT_ENTITIES`. Its entry is an `OPERATION` at `BEFORE_OPERATION`, after the existing delayed reveal and before the controller copies/narrows the original offer. The original loop and virtual single-selector calls retain their arguments, order, stopping condition, result and exception. The existing `parentChoiceId` links surviving inner selectors to this operation. Outer and inner observations overlap; their count is not a count of unique gameplay decisions.

## V6 received-argument permission

This increment introduced schema/profile V6 consistently, including hidden/unavailable contexts; current producers now use V9, retaining the [subsequent V7 history permission](Simulation-Entity-Selection-History.md) and the later zone-request/operation increments. V6 inherits the earlier profile fields and adds `{kind:ENTITY_BOUNDS,minimumPicks,maximumPicks,relatedPlayer}` in `policy.prompt`, with coverage `RECEIVED_ENTITY_BOUNDS_V1`, at this audited outer boundary only. Preserve the exact received integer bounds, including reversed/extreme values. Bind the optional role to an actual current player object; an equal raw ID from another game is insufficient. An unresolved role leaves the prompt unavailable, rather than inventing an association.

The existing boundary classification supplies rules or planning state. An immutable received-argument carrier identifies this scoped planning permission before suppliers are invoked. Other unaudited hypothetical prompt suppliers remain refused. Bounds describe this invocation; they do not certify rules legality, a legal returned list, effect semantics, mode/ability meaning or prior-selection history. Hidden views retain unestablished timing/basis and no policy. Disabled/copy capture bypasses offer, result and request projection.

The new operation's options contain diagnostic `{coverage,items,truncated,min,max,relatedPlayerId}`. Offered identities, membership/count/order and any existing option associations remain outside policy. No option bindings are authorized for this outer pool. The terminal selection contains `{coverage,items,selectedCount,truncated}`. `OBSERVED_RETURNED_ENTITY_PREFIX` describes a bounded prefix of actual returns; `UNAVAILABLE` describes unavailable reference capture with the observed list count, an empty prefix and `truncated=true`. Null callback results retain the ordinary declined lifecycle, distinct from a successfully returned empty list. Preserve returned duplicates/order and out-of-bound results; recording must not clamp or repair policy.

The diagnostic input/output cap is 256 references. Bounds consume the existing per-player traversal work, with no raised game allowance. An exhausted view does not suppress the operation, original callback or result. A fixed named accounting slot extends original-AI standalone accounting from 34 to 35 named boundaries; new empty slots are not serialized. Source entries count the new outer wrapper separately from its inner selectors. Collector receipts still mean writes returned, not merely event emission.
