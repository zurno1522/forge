## First implementation: controller-owned outer entity operation

Wrap `chooseEntitiesForEffect` as an `OPERATION` at `BEFORE_OPERATION`, after the existing delayed reveal and before copying/narrowing the offered collection. Capture its own entry and fresh permitted view. Reuse existing choice/action/assessment linkage and the inner callbacks' `parentChoiceId`; no new sequence ID, registry, database or inference from event order is needed. The outer operation and its inner selectors overlap and are not unique gameplay decisions.

Record the received minimum, maximum and related player, the diagnostic offered prefix, and the actual returned list with an explicit prefix/count/availability declaration. Preserve duplicates and return order. Keep offered membership/count/order diagnostic unless independently permitted; recording the operation is not a legal-domain grant. A new versioned prompt permission may project exactly the received scalar total bounds and the supplied player role. The role must bind by actual current player identity, not by matching a raw ID.

Use the existing rules/planning classification at the actual entry. Prepared evaluation/temporary scopes remain planning even during resolution. A received-argument carrier must identify any new planning permission before invoking suppliers; existing unsupported hypothetical prompt suppliers remain uninspected. Hidden input remains unavailable with unestablished timing/basis. All contexts use the new profile consistently so hidden family identity cannot be inferred from profile choice. Legacy profiles and inventories remain unchanged; introduce a conditional named inventory extension for the newly observed outer boundary.

Preserve the original loop, virtual `chooseSingleEntityForEffect` dispatch, removal/append order, stopping rule, original arguments and result/exception. The existing do/while can invoke an initial selector even when the maximum is zero; observation must describe actual calls rather than silently rewrite policy. Callback failure produces an error lifecycle, without changing the exception or replaying a pick. Disabled/copy/closed capture must not inspect offers, results or new request suppliers, and must not revive an abandoned record after recording is reenabled.

Add one fixed source-accounting boundary for the new outer adapter and reconcile its collector receipts with the existing inner calls. Extending the named table does not make uninstrumented callbacks observable. Define compatibility for V1 accounting and preserve old report bytes. No extra game allowance, raised cap or runtime optimization belongs in this increment; OPT-005 owns its expanded allocation/retention and CPU assessment.

## Second implementation: prior selections at the actual next pick

The controller's existing `selecteds` is the authoritative successful-return sequence. Keep observation bookkeeping bounded independently of the engine's result list. A private scope may retain a bounded prefix of selection receipts only until this operation exits; nested operations restore the previous scope in `finally`. Match the actual game, chooser and request/ability identity. Do not attach an unrelated callback merely because it uses a matching ability ID.

Capture card incarnation at the earlier return, before later mutation; keep exact object plus incarnation evidence. At the later selector, use its own fresh view and only directly proved, currently permitted public associations. Moved, stale, private, foreign or ambiguous references stay unresolved. Unknown identity does not erase the fact that an earlier return occurred, but a truncated/incomplete history must not be labeled complete. Local references belong to the new view and must never be copied from the outer view. A separate explicit permission/version must cover the chosen-history count/order and associations; diagnostic joins alone are insufficient.

Do not add independent model permission to an entity pool through this history feature. Keep ordinary local single-pick constraints distinct from total bounds and prior selections. Missing outer context stays unknown for legacy/direct callbacks. If a parent closes during a blocked receipt/projection read, timeout publication must finish; late work cannot emit an orphan, change the frozen parent or poison current observation health. All examples remain `trainingReady=false`.
